# External TypeScript author loader (A1 slice)

`createInstalledAuthorReplayPort({ projectRoot, module, exportName })` admits a TypeScript or JavaScript author module from an explicit trusted project. The project uses ESM, an exact `rsi-gear` dependency, and a package lock with integrity. Registry versions are accepted only as exact versions already installed; no registry access happens during admission. A `file:` tarball may live outside the project, but both its resolved path and SHA512-verified bytes are frozen. The installed package bytes and its closed author-entry runtime imports are sealed independently of the version string.

Admission may create one disposable compiler cache at `port.emittedCacheDir`, under `<projectRoot>/.gear/author-emit/<digest>`. A check/explain UI should show this location. Clearing the cache before a new admission is safe; deleting or altering it during a Campaign blocks replay until the same sealed bytes are restored. Admission does not create a Campaign journal, CAS, lock, budget, or physical operation. Every replay verifies source, prompt Markdown, lock/tarball, installed SDK, compiler, Node host, and emitted bytes before starting a fresh worker.

Only the installed `rsi-gear/algorithm/author` bare import and closed relative author imports are supported. The worker uses the same installed SDK entry for `replay` and the author definition. Other package imports, direct IO and dynamic imports are rejected by static checks; this reproducibility boundary is not an arbitrary-code security sandbox. `describeDefinition()` reads the algorithm declaration in a short-lived worker without running its body. Its SDK `apiVersion` field is metadata and does not override the port's explicit v2 wire version.
