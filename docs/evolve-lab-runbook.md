# Terminal-Bench 2.0 evolve lab

The local lab lives in `.evolve-lab` at the repository root and is ignored by
Git. It is intentionally isolated from the user's normal DSH and Hitch state.
The credential-free, reproducible source for the Luna setup is tracked under
[`examples/dsh-codex-luna`](../examples/dsh-codex-luna/README.md). Bootstrap
that example instead of copying an existing `.evolve-lab` directory.

## Pinned components

- DSH control plane: `@deepseek-ai/dsh@0.1.1-rc.2` with `dsh-codex@0.2.6`
- target DSH: `@deepseek-ai/dsh@0.1.1-rc.2` with `dsh-codex@0.2.6`
- Gear: the locally packed `dsh-plugin-refine@0.1.0`
- Hitch: a reviewed build that advertises `host-task-credential-helper-v1`;
  the tracked `agent-hitch@0.2.7` fallback does not support Codex task-start
  credentials
- Harbor: managed `0.21.0`
- target substrate commit: generated by `bootstrap-target.mjs`
- initial champion commit and manifest digest: generated by the same bootstrap
- seed: Terminal-Bench 2.0 `terminal-bench/regex-log`
- held-out: Terminal-Bench 2.0 `terminal-bench/log-summary-date-ranges`

The two task directories are disjoint local Harbor datasets. A round has four
evaluation phases: seed baseline, seed candidate, held-out baseline, and
held-out candidate. Each task has three native Hitch logical attempts.

The target repository is a small carrier Git repository whose package manifest
pins the public rc.2 DSH package, `dsh-codex`, and its compatible `pi-ai`; the
bootstrap installs them and commits the resulting lockfile. Its fixed
headless launcher verifies
`harness/manifest.json`, verifies every declared artifact, mounts
`harness/preset/agent.cordis.yml`, and only then makes the headless runner
eligible to start. Hitch uses its unmodified `deepseek` adapter and records the
carrier's exact commit.

The fixed carrier also selects DSH's `danger-full-access` permission preset
for target headless sessions only. Harbor's disposable Docker task container
is the target trial's security boundary, and Terminal-Bench tasks must be able
to modify container-owned paths such as `/etc`, `/git`, and service state. A
nested DSH `workspace-write` sandbox both blocks those legitimate task effects
and fails with `SandboxUnavailableError` in task images that contain neither a
usable Bubblewrap nor Landlock backend. This override lives in
`fixed/target.patch.yml`, outside the evolvable `harness/` tree; it does not
change the Web/Meta control plane or the candidate-editing sandbox.

The Terminal-Bench images are Linux/amd64. On Apple Silicon, Docker Desktop
must be able to run amd64 containers. This lab was validated with Docker
Desktop's classic image store because the legacy Terminal-Bench images did not
start reliably through the containerd image store. The local derived images
`gear-evolve/regex-log-node22:20251031` and
`gear-evolve/log-summary-date-ranges-node22:20251031` add Node `22.19.0`, pnpm
`11.7.0`, curl, Git, and CA certificates. Preinstalling those tools keeps Hitch
setup out of the task-time network path; it does not change either task or its
verifier.

## Models and ChatGPT login

The Refine meta agent, ordinary new DSH agents, and Hitch target trials all
default to `openai-codex/gpt-5.6-luna` in this lab.

The model and OAuth settings are environment variables:

- `GEAR_META_PROVIDER`, default `openai-codex`
- `GEAR_META_MODEL`, default `gpt-5.6-luna`
- `GEAR_TARGET_PROVIDER`, default `openai-codex`
- `GEAR_TARGET_MODEL`, default `gpt-5.6-luna`
- `GEAR_TARGET_CODEX_AUTH_FILE`, default
  `.evolve-lab/dsh-home/.openai-codex-auth.json`
- `GEAR_TARGET_CODEX_ENV`, default `DSH_OPENAI_CODEX_ACCESS_B64`
- `GEAR_TARGET_CODEX_EXPECTED_ACCOUNT_ID`, optional trusted account constraint
  required when separate wrapper invocations must remain on one account
- `GEAR_HITCH_EXECUTABLE`, the real Hitch executable behind
  `gear-hitch-codex`; default `hitch`
- `GEAR_DSH_CODEX_MODULE`, optional `dsh-codex` module override
- `DSH_CODEX_SEARCH_MODE`, default `live`; supported values are `cached`,
  `indexed`, and `live`

For example, Meta and target models can be overridden independently:

```sh
GEAR_META_MODEL=gpt-5.6-sol node examples/dsh-codex-luna/evolve.mjs web
GEAR_TARGET_MODEL=gpt-5.6-sol node examples/dsh-codex-luna/evolve.mjs web
```

Create the isolated runtime, profile, and exact-commit target repository by
following the tracked example README. Check or establish the isolated lab's
ChatGPT login before starting Web:

```sh
node examples/dsh-codex-luna/evolve.mjs codex-status
node examples/dsh-codex-luna/evolve.mjs codex-login
```

For a terminal without a usable browser, use:

```sh
node examples/dsh-codex-luna/evolve.mjs codex-device-login
```

These commands use the community `dsh-codex` plugin and do not require an
`OPENAI_API_KEY`.

Configure `hitch.executable` to the installed `gear-hitch-codex` binary and
set `GEAR_HITCH_EXECUTABLE` to the real Hitch binary. This integration requires
`hitch.controlPlane.mode: direct` and a Hitch build whose doctor output includes
`host-task-credential-helper-v1`. The published `agent-hitch@0.2.7` in the
tracked lab manifest is not sufficient; follow the example README to install
the reviewed Hitch checkout until this capability is released.

Before direct `eval run` or `eval rerun`, the wrapper checks the host login and
capability. It then registers a host-only credential helper without exporting
an eval-wide bearer. When each actual Target is ready to start, Hitch requests
enough validity for that task's remaining budget and refresh margin. The helper
uses the existing locked dsh-codex store, so queued tasks and all three native
attempts get a fresh check. A refresh updates the persistent host access while
the rotating refresh token stays on the host. If the resulting access still
cannot cover the requested budget, the task fails explicitly.

Infrastructure retries remain zero; the wrapper adds zero when omitted and
rejects nonzero values. The `--pass-env` entry declares the credential name,
while Hitch keeps its static value empty and fills only the individual Target
environment immediately before launch.

Hitch receives `DSH_OPENAI_CODEX_ACCESS_B64`, an access-only envelope containing
the short-lived bearer, expiry, and account id. It never receives the OAuth
document or refresh token. The target writes a disposable dsh-codex document
with a deliberately unusable refresh placeholder, so it can use the bearer but
cannot rotate the host login. `eval submit`, `eval run --daemon`, and daemon
reruns fail explicitly; other Hitch commands are transparent pass-throughs. The
wrapper also sets `GEAR_TARGET_CODEX_ENV` in the Hitch child environment, so the
documented default `passEnv` list works without a separate export.

For a long experiment, set `GEAR_TARGET_CODEX_EXPECTED_ACCOUNT_ID` from the
trusted provisioning record. The wrapper always prevents an account switch
within one process; the explicit value also binds separately invoked eval and
rerun processes. Without it, each new wrapper process adopts the account active
at its own preflight.

## Run

First start Docker Desktop and complete the ChatGPT login above. Then run:

```sh
node examples/dsh-codex-luna/evolve.mjs doctor
```

Run all lab commands from the Gear repository root.

Continue only when the JSON says `"ready": true`. Start the isolated DSH
control plane:

```sh
node examples/dsh-codex-luna/evolve.mjs web
```

Open `http://127.0.0.1:3080`, enter an already persisted ordinary session, and
submit:

```text
/refine --rounds 1 --budget 900000 --target context
```

The command returns a round id. Inspect it with:

```text
/refine status <round-id>
```

Round state is under `.evolve-lab/state/refine`; Hitch evidence and prepared
artifacts are under `.evolve-lab/hitch-home`. The target repository must remain
clean before starting a round.

The meta IPython helper runs inside the required OS sandbox. Its actual cwd is
a per-session directory below `.evolve-lab/state/refine/meta-notebooks`, and it
cannot directly read the surrounding lab, DSH session logs, target repository,
Hitch state, held-out dataset, credentials, or host environment. Champion and
trajectory data must cross the typed Host Bridge. On macOS this requires the
built-in `sandbox-exec`; on Linux install Bubblewrap, `socat`, and ripgrep.

For target trials, `gear-hitch-codex` reads the plugin-owned credential from
`GEAR_TARGET_CODEX_AUTH_FILE`, refreshes the persistent host document when
needed, and transports only the current access envelope as a redacted Hitch
credential. The target launcher writes it with mode `0600` into that disposable
run's isolated `DSH_HOME`. The flow never reads or copies `~/.codex/auth.json`,
never distributes a rotating refresh token, never requires an
`OPENAI_API_KEY`, and does not print the bearer. Setting
`GEAR_TARGET_PROVIDER=deepseek-official` retains the previous `DEEPSEEK_API_KEY`
path as an explicit fallback configuration.

Each container receives a task-start access snapshot. Long queue waits do not
consume that Target's credential lifetime, but the access is still
non-refreshable inside the container and must cover the task budget requested
by Hitch. A daemon deployment and already-running remote workers are outside
this wrapper integration.

## Useful checks

```sh
node examples/dsh-codex-luna/evolve.mjs dump
node examples/dsh-codex-luna/evolve.mjs prepare
git -C .evolve-lab/target-dsh status --short
```

`dump` verifies the final DSH composition without starting a server. `prepare`
forces Hitch to resolve and build the exact initial champion; its output must
report `observed_version: 0.1.1-rc.2`.
