## Gear 完整比较与资源边界

[Gear Linux 证据](mlebench-gear-linux-2026-11-09.json) 和 `tests/integration/canaries/mlebench-linux.mjs` 覆盖真实公共导入、apply/check、编译、候选注入、重新封存、Hitch 准入与执行、独立 verifier、公共产物导出、Gear 指标提取及目标聚合。

基线与两个实际 Git 候选各执行两次，共六个完整任务，零重试、零模型调用。六份 CSV 均核验摘要；共享一个正式评估身份，具有三个候选身份和六个执行身份，且原始任务与 Gear 材料化任务的评估身份一致。这里的合成数据和确定性 Agent 验证执行与比较机制，不代表真实模型质量提升。启动前发现的配置、容量与源代码漂移拒绝另行保留，没有混入六次实际任务。

资源清单仅接受当前 schema `3`。Gear 使用 Hitch 的公共资源 SDK 验证源描述和派生身份，不复制资源权限或摘要算法；资源锁及私有资源引用保持不变。材料化之前保留正式评估输入；实际候选树进入候选身份。资源任务显式使用 `backend` 构建，恢复前核对数据摘要、运行时、请求和已准备产物。

已配置项目使用选定 profile 的 Hitch SDK。执行阶段的编译、规划和封存还绑定到已观察的 controller 身份，并在 SDK 调用前后检查身份一致；并发项目不修改进程全局环境。损坏的已配置 profile 不能回退到 PATH 中的其他安装。

## 可选可信训练服务

Hitch 的 `docs/evidence/mlebench-trusted-linux-2026-11-09.json` 记录真实隔离服务、独立 verifier 和故障恢复验证。覆盖范围明确为 `trusted-service-top-level-attempts`，只支持声明的闭合数值分类方法，不接受任意用户源码或 pickle，也不声称覆盖 Agent 自行启动的全部训练。

实际服务验证包括五折加三折 CV、一次最终完整拟合，共九次计费 fit；计划、封存和重放不产生额外 fit。并发请求原子预留额度；失败或取消后的未知动作保留已消耗和未释放额度，不能解释为零。相同行分配在恢复中保持；获准改变 CV 会生成新的动作身份。冻结交付验证所选方法、参数、源码/依赖版本、最终拟合和 CSV 摘要。CPU、内存、网络和挂载限制来自实际 Docker 观察，不依赖 Agent 自报。

缺少相应可信能力的硬 fit 上限、可信 CV 或冻结交付要求在模型启动前拒绝。关闭这些约束时，普通 sklearn Pipeline 和包含合法 Python lambda 的程序正常执行。

最后的真实容器攻击用例在 Agent 可写日志中放置了完整的伪造零消耗收据。独立 verifier 和公共证据 API 仍使用宿主未挂载的 trial 根目录中的权威收据，正确记录九次消耗；日志伪造及符号链接不能替代或覆盖它。
