# Failure → data → harness：真实 LLM 对照结果

**闭环已运行；本次未观察到相对初始 harness 的测试提升，也不能证明 failure 生成优于固定数据或随机生成。** 模型权重始终不变，只修改 developer prompt。针对性练习出现局部修复，但没有转化为这份留出集上的增益。

## 最终测试

模型为 `gpt-6-astra`，reasoning effort 为 `low`。四组使用完全相同的 48 道 IFEval 原始测试题、101 条约束和官方 strict 验证器。优化完成后才开始最终测试。

| 组别 | 通过题数 | Prompt accuracy | Instruction accuracy | 最终 harness |
| --- | ---: | ---: | ---: | --- |
| 初始 baseline | 46/48 | 95.83% | 98.02% | 初始 80 字符 prompt |
| 固定数据 fixed | 45/48 | 93.75% | 97.03% | 与初始相同 |
| 随机生成 random | 45/48 | 93.75% | 97.03% | 与初始相同 |
| failure 生成 | 46/48 | 95.83% | 98.02% | 第一轮采纳的 1713 字符 prompt |

failure 与初始组在全部 48 题上的通过／失败标签完全一致。两组共同未通过 `ifeval-3456` 的全大写约束，以及 `ifeval-2616` 的高亮段数约束。fixed 另在 `ifeval-1813` 的全大写检查失分；random 另在 `ifeval-1964` 的字母频次检查失分。三个使用相同初始 prompt 的独立评测得到 46、45、45，说明一题的差异本身不足以支持策略优势。

| failure 相对 | 修复 / 退步 | 净变化（百分点） | 配对 bootstrap 95% 区间（百分点） | Exact McNemar p |
| --- | ---: | ---: | ---: | ---: |
| baseline | 0 / 0 | 0.00 | [0.00, 0.00] | 1.00 |
| fixed | 1 / 0 | +2.08 | [0.00, 6.25] | 1.00 |
| random | 1 / 0 | +2.08 | [0.00, 6.25] | 1.00 |

区间来自 5000 次按题配对重采样，p 值是未做多重比较调整的双侧精确值。baseline 一行的退化区间源于本次观测差值全为零，**不表示真实效应的不确定性为零**；这些统计不覆盖模型重复采样、优化随机性或其他任务分布。

## 实际发生的改进

初始训练集通过 7/8。失败样本 `ifeval-3414` 要求至少 5 个、少于 11 个大写词。按官方分词器独立重算，实际有 13 个：8 个强调词和 5 个代词 `I`。诊断器将失败归因于遗漏附带的大写词，并明确这是一次观测；它的文字说明却误写成 8 + 4 = 12。因此诊断文字本身不能当作精确计数证据，准入与评分始终依据官方验证器。原始诊断文本也保留在证据中。

failure 组围绕这个来源模板生成 8 个新主题任务；参考答案均通过官方检查。当前模型在新题上通过 **6/8**。优化器据此产生通用检查策略：明确上下界、统计整个回答中的全部匹配项、计入代词与缩写、修改后重新计数。候选没有硬编码训练题的答案或具体计数值，开发集仍通过 8/8，因此被采纳。

对同一批练习重新作答后通过 **8/8**。这是一次局部修复观测，不足以单独建立因果或泛化结论。第二轮已无当前练习失败，failure 组按预定规则转为随机生成；在这批新题上通过 7/8，剩余错误是段落数量。第二轮未采纳新 harness，反馈复测仍为 7/8。

## 对照的关键限制

**六次候选中五次因超长无效，显著限制了数据策略的归因。** 所有组都要求 harness 不超过 1800 字符；无效候选消耗本轮提案机会，不修复重试，保留当前 harness，并继续相同数量的评测调用。

| 组别 | 第一轮候选字符数 / 采纳 | 第二轮候选字符数 / 采纳 |
| --- | --- | --- |
| fixed | 1897 / 否，超长 | 1953 / 否，超长 |
| random | 1956 / 否，超长 | 1868 / 否，超长 |
| failure | 1713 / 是 | 1841 / 否，超长 |

因此，本轮不能把 fixed/random 没有形成新 harness 解释为其数据无效，也不能把 failure 的候选格式合格解释为生成策略已经胜出。baseline 开发集已是 8/8，采纳规则只能筛除明显退步，难以区分改善。测试 baseline 达到 95.83%，提升空间也很小。

这是一轮探索性实验：一个切分／模板采样种子，一次两轮优化，模型调用未设置可复现的采样 seed。它只验证指定的格式与词数等约束；不评价答案的整体内容质量，不覆盖工具调度或 harness 代码演化。公开 IFEval 子集结果不等于全量官方榜单成绩。

## 冻结的实验设置

- IFEval 来自 [Google Research 固定提交](https://github.com/google-research/google-research/tree/e6890f85757dd84e27ca6df2dd30651dafad28e0/instruction_following_eval)。筛选出 113 个满足当前确定性验证和长度规则的任务，以 seed `20261119` 切成 8 train、8 dev、48 test。
- 隔离的是原始任务及其生成变体的 source family；不同集合可以共享约束类型。生成器与优化器不接收开发／测试题和答案。调用方仅以留出题文本做精确重复排除。
- fixed 每轮使用同一训练集；random 从训练来源均匀抽样约束模板，生成器不接收失败材料；failure 从当前真实失败选择模板，无失败时显式回退 random。
- 两轮各组实际都使用 8 条学习样本、1 次候选提案、8 次开发评测、8 次更新后反馈作答。候选在开发集分数不降时采纳；无效候选不采纳。优化器只接收学生回答及检查结果，不接收生成器的参考答案。
- 共生成 32 条数据，四批均有 8 个不同的预定 slot。参考答案通过官方检查；校准要求空答案及至少一个非空错误控制被拒绝。新颖性只有精确文本去重，没有证明语义新颖性。
- 所有角色使用相同模型与 effort，每题独立会话，工具关闭。并发上限 4、单次超时 240 秒、请求上限 380。
- 最终测试前冻结了全部 harness，之后没有依据测试结果修改它们。调用方源码 SHA256 为 `48333d67f0d419bf3dd7c4fab4d6848a0917fceb51714758a9c86171cd93d066`。curriculum 核心使用本分支已有提交 `4ae640cfa`。

开发过程中先发现缺少 NLTK 表资源，补齐固定摘要的资源并将非空验证器预检提前。随后首个优化候选超长导致停止，补充了上述对所有组统一的无效候选处理规则。该修订发生在首个候选的开发评测与全部最终测试之前；28 份已完成且请求完全一致的回执经校验后复用，没有重新调用。修订身份与继承回执摘要保存在证据的 `amendment` 中。预检失败与连通性探测不计入效果分数，其用量未完整记录，也不包含在下表主实验用量内。

## 实际调用用量

| 归属 | 调用次数 | 原生 input tokens | 原生 output tokens |
| --- | ---: | ---: | ---: |
| 共享初始 train/dev 与 baseline 测试 | 64 | 665,133 | 14,162 |
| fixed | 98 | 1,033,448 | 24,285 |
| random（含 2 次生成） | 100 | 1,054,392 | 22,449 |
| failure（含 2 次生成、1 次诊断） | 101 | 1,095,035 | 23,266 |
| 合计 | 363 | 3,848,008 | 84,162 |

全部 363 次有原生 token 回执；其中 352 次是学生评测。cached input 为 2,696,448，已经包含在 input tokens 中，不能再相加。两组生成和诊断的额外调用共 5 次、68,856 个 input+output tokens。三组匹配的是任务和提案／评测调用数量，不是严格相等的 token 总量。本报告不推算账单金额。

离线复核已核对 363 份请求／回执、重新判分全部 352 份评测回答和生成参考答案，检查切分、共同样本数、验证证据摘要、最终 harness 和汇总一致性。导出包含 24 个评测批次。9 项新增离线测试与 17 项 curriculum 测试通过，Python 包边界和 Ruff 检查通过。

`gear.curriculum` 仍只包含算子与输入输出。模型调用、任务转换、验证、恢复和 prompt 搜索均在示例调用方，没有新增 adapters 层。这是反思式 prompt 搜索，未宣称完整复现 [GEPA](https://github.com/gepa-ai/gepa) 或 [ACE](https://github.com/ace-agent/ace)。二者分别提供文本参数搜索和上下文 playbook 更新的开源实现，均可用于不更新模型权重的 harness 改进。

后续若要识别数据生成的独立收益，应先提高三组候选格式合格率，再在另行固定、具有足够提升空间的任务集上做多次独立优化。当前结果不支持对 failure 生成作优势结论。
