# Fixed-Harness Slime GRPO (experimental)

`fixedHarnessGrpoRecipe` is the public TypeScript recipe for one independent training candidate. It runs `training.slime`, seals a candidate `BindingSet`, evaluates the frozen baseline and candidate on dev, applies the dev gate, evaluates both on held-out only when the gate passes, and transitions the active learner binding only after `decideModel` accepts. It never reads or writes the legacy coordinator's champion, and it does not publish or deploy a model.

The learner slot holds a `training.model-binding.v1` artifact created by `sealTrainingModelBinding(artifacts, trainingStore, modelRef)`. The immutable fixed-Harness slot holds `training.fixed-harness.v1` from `sealTrainingHarnessBinding`. Both bindings and the training plan must reference the same actual training CAS objects. The recipe's candidate evaluation uses an explicit candidate BindingSet; the baseline uses the original frozen BindingSet.

Construct an `AlgorithmRuntime` with the recipe, `SlimeTrainingOperationProvider`, and `ModelEvaluationOperationProvider`. For a local job backend, supply `localSlimeJobLookup(actualSlimeTrainer)`; for a model-node backend, supply `nodeSlimeJobLookup(actualNodeTrainer)`. The evaluation provider needs an actual `HitchModelEvaluator` with `cancel`/release confirmation. A user-provided `TrainingJobLookup` is useful only for controlled tests; it is not evidence of a real Slime job. The independent provider submits and reconciles using the original operation-derived request/key. The V2 node adapter replays ordered start sequence 0 and ordered pause sequence 1, and probes the frozen node runtime on lookup.

Campaign budget dimensions are deliberately source-specific: `trainingGpuSeconds`, `rolloutTokens`, and `groupResamples` use source `training.slime`; `evaluationGpuSeconds` uses source `training.evaluate`. Configure the sum of the training and evaluation GPU limits against any external total allocation. These are stop budgets backed by cumulative operation receipts, not a claim that arbitrary GPU processes can be hard-fenced at exact seconds.

`tests/unit/algorithm-training.spec.ts` is an executable CPU contract fixture. It proves W0 remains the independent parent when an old experiment's champion is Wold, including paired evaluation, no-candidate, loss of submit response, cancellation, and legacy accounting. The fixture does not run Slime/Hitch or claim GPU reproducibility. A real run still needs the existing Python bridge/runtime lock, model-node probe or local package/config identity, authorized train data, and the actual Hitch/Slime services.
