# Data analysis pipeline contract

`experiment(action="run", plan=...)` accepts an explicit list of variants. Build a bounded model/parameter search and include a baseline when useful. A variant declares inputSchema, preprocessing, features, model, hyperparameters, prediction and seed. The plan declares version:1, entrypoint, variants, validation:{kind,method,folds,shuffle,seed,fraction?}, selection:"best_mean_utility", seed, maxFits and refitReserve:1. Copy the supported validation fields from task_inspect; omit fraction for K-fold. The top-level seed and variant seeds control models, separately from the runtime's split seed.

Write a Python factory `build_pipeline(config)` returning an unfitted estimator with fit/predict (and predict_proba when requested). Put learned preprocessing/features in its sklearn Pipeline. The runtime clones and fits it inside each training fold; do not fit, search, read data files or select a configuration inside the factory. Return the same unfitted construction for the same config. Config is the concrete choice, not a search space. The runtime records get_params before/after fit, actual calls, predictions and cost. Custom transformers belong in the source closure. All code and dependencies are frozen by source and runtime digests.

Gear freezes the outer evaluation policy and Hitch materializes its row assignments. Both harnesses, all experiments and all variants share that plan. The default is five shuffled folds; the configured plan may instead use another fold count or a holdout fraction. Recovery keeps the exact original assignments. Do not replace the split, change its seed, choose group/time validation or reserve an additional validation/test subset. Diagnose dependence and leakage as limitations of the fixed protocol. Prediction is {kind:"label"}, {kind:"probability",positiveLabel:1,threshold:0.5}, or {kind:"regression"}. Probability without threshold produces probabilities; with threshold it produces labels.

Select by mean utility across the frozen evaluation folds; inspect fold scores, standard deviation and OOF predictions. There is no extra holdout fit or local test score. For N variants reserve at least N*validation.folds+1 fits, including one final-refit reserve. `select` must name the evaluated resolved variant or a compatible incumbent under the same frozen outer policy. Scores from other evaluation versions remain searchable but cannot rank/select a source until it is re-evaluated under the current policy. CV used for model selection is development evidence, not an independent generalization estimate or a Kaggle score. Final refit fits the frozen choice once on all training rows and predicts the official unlabeled test; it never searches. EDA uses analysis_execute with fits disabled; train through experiment.run.

Use experiment.record for notes and stage state; workspace artifacts are sealed automatically. Use task_inspect(stage=...,resource=...) for one stage or this skill, and experiment.get for full paged evidence. Notes do not set scores.

To persist a stage, call the `experiment` tool with this argument shape:
```json
{"action":"record","stage":{"stage":"eda","status":"completed","artifacts":["<digest returned by analysis_execute>"],"conclusion":"<findings and their modeling implications>"}}
```
Valid statuses are not_started, running, completed, reused, skipped and failed. Use real, visible artifact digests from analysis_execute, experiment.run or experiment.get; completed/reused require evidence. EDA completion needs successful analysis output, not just code or a note. For reused/skipped/failed, include a reason. Optional inputs records stage-specific versions. For reuse, keep the selected stageState's inputs and artifacts unchanged. Changing inputs/evidence invalidates dependent stages. The record response returns the persisted workflow; rollout_finish seals it into the experiment for the next checkpoint. Notes alone do not change stage status.
