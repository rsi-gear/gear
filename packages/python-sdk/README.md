# gear-algorithm (experimental)

This is the lightweight Python author package for Gear's experimental Campaign runtime. It has no Torch, CUDA, Optuna or training dependencies. The Node/TypeScript Gear host and its CLI are installed separately; installing this wheel does not install that host.

An algorithm exports an object with `describe()`, `initialize(context)` and `reduce(context)`. `describe()` returns `AlgorithmManifest` with state/config/binding schemas. `@task(name, kind=...)` names a pure input builder that emits an `OperationIntent`; `@decision(name)` names a pure decision function; `parallel()` gives a stable key order. Return `AlgorithmDecision` or use `advance()`. Side effects belong in providers, and Gear resumes at step boundaries rather than inside a Python stack frame.

A policy hook uses `@component(id=..., input_schema=..., output_schema=..., scope=...)` on one function. The loader supplies implementation and environment digests from observed files, interpreter and imported modules. Hook input/output schemas and scope must match the recipe's declared slot. `policy.decide` is a normal durable operation: a committed choice is reused on resume; a started call without a sealed result stays `unknown` and needs reconciliation.

A Python provider implements `describe/preflight/submit/inspect/cancel/collect`. `ProviderManifest` declares one operation kind, schemas, metered dimensions, optional enforceable hard dimensions and trusted-local/external execution. `ArtifactClient` seals/reads content through a host-authorized bridge; it does not require a private TypeScript registry. `DurableLocalProvider` supplies fsynced started/result records for synchronous deterministic local work. It deliberately does not implement unknown external sends, GPU budgets or background jobs. For an external system, implement stable idempotency and inspect against that system and report real usage receipts. `gear_algorithm.testkit` checks duplicate submit, input drift, dropped reply and restart inspection.

The worker uses an authenticated, length-limited TCP connection bound to `127.0.0.1`; stdout and stderr are logs. A single frame is limited to 4 MiB, including base64 artifact transfer. Transfer large checkpoints through a provider's own validated artifact path. The worker runs trusted local code and is not an OS sandbox. The wire accepts only finite, safe-range JSON values and refs, never pickle or Python objects. The TS host computes Gear digests.

Python `interpreter` is an absolute path, a path relative to `gear.algorithm.json`, or a command resolved from `PATH`. Python `module` is a dotted import or a `.py` path; relative `.py` paths are resolved from the configuration directory. `export` is one public Python identifier. The project source closure includes Python/ESM/JSON/TOML/YAML/lock and `requirements*.txt` files under that directory, excluding `.gear`, virtual environments, `node_modules` and caches. Additional data files used by an algorithm must be listed in the entry's `resources`; those files are hashed. Installed Python modules loaded when the export is imported are also hashed. Load scientific dependencies at import time so `check` can catch missing packages and record them in the identity. `check` imports trusted modules but never submits an operation or calls a paid model.

Start from `examples/algorithms/python-toy` or run `algorithm init DIRECTORY python`. Build the wheel with `python -m pip wheel --no-deps -w dist packages/python-sdk`, install it into the selected interpreter, then use the host's experimental `node lib/algorithm/cli.js check|run|resume gear.algorithm.json` entry. Public contracts remain experimental pending independent provider and real training acceptance.

`algorithm init` writes a new globally unique `campaignId` and a matching `.gear` state path. Preserve that ID and the frozen configuration when resuming. If you construct `CampaignSpec` directly, assign each new campaign a globally unique ID; external provider idempotency keys derive from it.
